# oh-story 按建议改稿：只改真建议

日期：2026-08-14  
状态：已确认（用户批准 2026-08-14）  
前置：`2026-08-14-oh-story-apply-from-review-design.md`  
原因：第 1 章走「审稿 → 整章改稿 → 去AI」后朱雀人工率 0。审稿只提了两处可执行建议，模型却通篇换词。

## 目标

按建议改稿仍输出整章正文，但**只动审稿「修改建议」里的可执行条目**。未点名的句子和段落必须原样保留。禁止整章重写、禁止通篇抛光。

## 已确认决策

1. 采用「提示约束 + 段落保留门禁」，不做逐条补丁引擎。
2. 「真正的建议」只认报告「修改建议」里要改的条目（优化 / 微调 / 删 / 补 / 改）。写着「保持」「不要改」的条目不改。Findings、格式勾选、基础检查只作证据。
3. 仍输出 `### 修订后全文`，仍按原抽取规则写入章节。
4. 原文按空行切段。原文段落数 ≥ 8 时，至少 70% 的原段落必须在新稿里原句出现；否则拒绝写入。
5. 原文不足 8 段时不做幅度门禁（单测短文仍可改）。
6. 拒绝码：`OH_STORY_APPLY_REWROTE_TOO_MUCH`。用户文案：`这次改动太大，像整章重写。请再试一次`。
7. 匹配审稿、不自动连跑、不加理论课、不读 SKILL.md、朱雀只参考：沿用原 spec。

## 提示

把「根据审稿报告里的修改建议改写整章」改成：

- 只改「修改建议」里的可执行条目
- 保持类条目、Findings、格式勾选不当指令
- 未点名的句子和段落原样保留
- 禁止整章重写、禁止通篇换词抛光

## 门禁

在 `extractOhStoryApplyChapterText` 之后、`updateChapterText` 之前：

```ts
ohStoryApplyRewroteTooMuch(original, next) === true
  → throw OH_STORY_APPLY_REWROTE_TOO_MUCH
  → 不写章
```

路由映射 409，前端 toast 同一句文案。

## 明确不做

- 逐条补丁 / 旧 `surgical_patch`
- 因朱雀分回退或自动再审、自动去AI
- 恢复理论 `must_fix`
- 本轮不自动恢复 7.5% 旧稿（版本仍在，用户要再恢复）

## 验收

1. 提示不再出现「改写整章」。
2. 8 段原文只改 2 段：写入成功。
3. 8 段原文改掉 4 段或通篇换词：正文不变，提示改动太大。
4. 无审稿 / 哈希不匹配 / 空输出 / 报告型输出：行为与原 spec 相同。
