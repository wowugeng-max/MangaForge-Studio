# 质检修订条收敛到 oh-story 按钮

日期：2026-08-14  
状态：已确认（用户批准 2026-08-14）  
前置：`2026-08-14-oh-story-core-skill-shell-design.md`（方案 B）  
实测：第 1 章去AI 后朱雀人工率 7.5%，用户认为整体观感提升，方向正确。

## 目标

质检修订条只服务 oh-story 核心动作。旧的 MangaForge 修订入口从这条 UI 拿掉，避免再走「一键修订 / 按报告补丁」。

## 已确认决策

1. **只改「质检修订」这一条**。章节顶栏（生成 / 补齐材料 / 更多）和其余工作台不动。
2. **可点按钮只留两个**：`oh-story 审稿`、`oh-story 去AI`。
3. **分数继续显示**，文案仍是「参考，不自动改稿」。
4. **展开区只读**：可看分数、状态、问题列表；不再提供任何改稿/复检/补材料按钮。
5. **后端修订接口先不删**。这次只收敛 UI，不拆 `editor_revision` API。

## 顶栏

保留：

- 标题「质检修订」
- 参考分 pills + 「参考，不自动改稿」
- `oh-story 审稿`
- `oh-story 去AI`

删除：

- 「一键修订」
- 顶栏「质检 / 复检 / 重新质检」（`!canRevise` 时的那个按钮）

## 展开区

保留（只读）：

- 报告摘要、分数、状态标签
- 质检问题列表（不再挂「按这条修订」）
- 工艺分 / 维度分（若已有）
- 若仍有进行中的旧 `editor_revision` 任务，保留状态条和取消/重试，避免卡住的旧任务无法收尾

删除：

- 「立即质检 / 复检当前版本 / 重新质检」
- 「按报告修订 / 按报告+自定义修订 / 已用于修订」
- 「生成编辑报告」
- 「历史记录」
- 修订芯片：补动作 / 砍描写 / 提节奏 / 补后果
- 自定义修订输入和预设（清英文夹杂 / 强接开篇 / 去进度回放）
- 「一键补材料」及「先点立即质检再修订」这类行动文案

空状态改成说明：没有参考分时仍可直接点审稿或去AI，不必先质检。

## 不改

- `/api/novel/oh-story/core/review`、`/deslop` 行为（含 `model_id`、润色后全文抽取、空结果不落库）
- 章节顶栏、任务中心、写作 skill 市场页
- 朱雀 / 指纹计算（继续当参考，不回退、不拦入库）

## 验收

`workspace-center-quality-revision-panel` 测试：

- 有 `oh-story 审稿`、`oh-story 去AI`、`参考，不自动改稿`
- 没有 `一键修订`、`复检`、`按报告修订`、`生成编辑报告`、`补动作`、`一键补材料`

手工：打开项目 3 第 1 章质检修订条，只能看到两个 oh-story 按钮；展开后能看参考分和问题，点不到旧修订。
