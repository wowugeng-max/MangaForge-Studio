# 编辑器修订 JSON 双引号恢复设计

日期：2026-07-30
状态：已确认，待实施
范围：单章编辑器修订候选的 JSON 解析与安全准入

## 1. 背景与现场证据

单章修订任务 `#753` 的模型响应以 `end_turn` 正常结束，流尾包含闭合的 `}` 与 Markdown JSON 围栏，不属于 token 截断。响应正文中的对白使用了未转义的英文双引号，例如 `"第三位天选者，今晚就会被选中。"`，导致整体 `JSON.parse` 失败。

现有恢复器把 `chapter_text` 的第一个未转义双引号误当成字段结束符，只恢复了约 369 个正文字符，并设置 `recovered_from_partial_json`。候选准入随后以 `REVISION_PARTIAL_JSON_RECOVERY` 安全拒绝。拒绝行为避免了再次覆盖正文，但也把“完整响应中的字符串转义错误”与“真正不完整的 JSON”混为一类。

用户将自行从历史版本回滚正文。本次不修改数据库、不执行历史恢复，也不改变候选长度门。

## 2. 目标

1. 正常结束、外壳完整、仅因正文英文双引号或原始换行导致 JSON 字符串非法时，确定性恢复完整 `chapter_text`。
2. `max_tokens`、`length`、开放字符串、缺少 JSON 结尾或存在 `incomplete_details` 时继续拒绝。
3. 精确的 Markdown JSON 围栏只视为传输外壳；正文自身包含代码围栏时继续拒绝。
4. 不增加第二次模型调用，不延长修订链路。
5. 不放宽普通局部修订的长度、结尾、补丁唯一性或源版本保护。

## 3. 方案

### 3.1 恢复最长的结构化字符串字段

部分 JSON 恢复时，同时计算：

- 按 JSON 引号扫描得到的闭合字符串；
- 按后续已知字段边界定位得到的结构化字符串。

始终选择两者中更长的结果，不再以“已恢复超过 200 字”为由跳过结构化恢复。这样，正文较晚位置出现未转义英文双引号时，不会只保留引号前缀。

### 3.2 区分完整但非法与真正不完整

候选只有同时满足以下条件，才允许把恢复结果视为“完整但 JSON 字符串非法”：

- transport 已通过现有完整性检查；
- finish reason 为正常完成状态；
- 不存在 `partial_json_open_string_recovered`；
- 去掉精确 JSON 围栏后，响应以 `{` 开始并以 `}` 结束；
- 恢复结果能形成可应用的完整候选。

其他所有 `recovered_from_partial_json` 仍以 `REVISION_PARTIAL_JSON_RECOVERY` 拒绝。

### 3.3 围栏处理

允许响应整体是精确的 ` ```json ... ``` ` 传输围栏。以下情况仍拒绝：

- `chapter_text` 自身含代码围栏；
- JSON 前后带“以下是修订稿”等聊天说明；
- 正文仍是 JSON object/array 外壳。

### 3.4 提示词加固

编辑器修订提示词补充：

- 只输出 JSON object，不输出 Markdown 围栏；
- 正文对白优先使用中文引号 `“”`；
- 使用英文双引号时必须按 JSON 规则转义。

提示词仅降低复发概率，确定性恢复仍是最终保护。

## 4. 数据流与失败语义

```text
模型正常完成
  -> 标准 JSON.parse
  -> 失败时执行结构化字段恢复
  -> 判断外壳是否完整
  -> 完整但字符串非法：进入现有候选准入
  -> 真正不完整：REVISION_PARTIAL_JSON_RECOVERY
```

无论哪种解析路径，只有通过现有 transport、补丁应用、长度、正文包装和结尾检查后才能写入章节。失败时章节与版本表保持不变。

## 5. 测试

新增回归测试覆盖：

1. 正文超过 200 字后出现未转义英文双引号，仍恢复完整正文；
2. 正常 `end_turn`、完整 JSON 外壳和精确 JSON 围栏可通过准入；
3. 相同内容在 `max_tokens` 下仍被拒绝；
4. 开放 `chapter_text` 字符串仍被拒绝；
5. 缺少顶层 `}` 的响应仍被拒绝；
6. 正文自身代码围栏和聊天说明仍被拒绝；
7. 普通合法 JSON 与现有候选长度门行为不变。

## 6. 非目标

- 不回滚或修改第一章历史版本；
- 不调整结构重写的候选长度区间；
- 不增加模型格式修复重试；
- 不修改其他章节、Story State 或后置质检范围；
- 不放宽真正截断响应的安全门。
