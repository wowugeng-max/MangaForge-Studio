# 小说工作台设定资产：本章调用确认设计

## 背景

设定资产页已经具备角色、能力、物品、势力、地点、剧情线、新资产候选、状态变更、本章调用等数据能力，但当前页面主要按资产类型列表展示。用户在写正文前真正需要确认的是“这一章哪些资产必须出现、哪些不能揭示、哪些要推进或回收”。因此第一版改造不扩大后端能力，优先把现有数据组织成面向章节写作的调度确认界面。

## 目标

- 让用户在写正文前快速确认本章资产调度是否正确。
- 降低长资产名、长约束、长状态字段带来的阅读负担。
- 保留现有新增、编辑、删除、自动匹配、保存本章调用、新资产候选和状态变更能力。
- 不改后端接口和数据结构，第一版只调整前端信息结构、展示层和交互入口。

## 非目标

- 不做拖拽式看板。
- 不新增资产关系图、时间线图或复杂可视化图谱。
- 不重写设定编辑表单的数据模型。
- 不改变正文生成链路对章节调用数据的读取方式。

## 推荐方案

采用“本章调度台 + 资产池浏览”的双层结构。

页面默认先回答“本章怎么用资产”，再提供“按类型浏览资产池”。顶部区域展示本章调用统计和筛选入口；主体优先展示已配置或被筛选命中的资产卡片；类型 Tabs 仍保留，但从主要浏览方式降级为资产池入口。

## 页面结构

### 1. 本章调用确认区

位于设定工坊说明和命令按钮下方，替代当前单一计数卡。

内容包括：

- 当前章节标题：例如 `第 1 章 · 异象初临`。
- 汇总计数：`已配置`、`必用`、`禁揭`、`推进`、`埋线`、`回收`、`暂停`。
- 筛选按钮：`全部`、`必用`、`禁揭`、`推进`、`埋线`、`回收`、`未配置`。
- 主操作：`保存本章调用`，在该区域保持明显可见。

筛选按钮只改变本地展示，不立即保存数据。所有调用状态仍沿用现有 `usage` state，并通过现有保存接口提交。

### 2. 资产调度卡片

每个资产用紧凑卡片展示，目标是先看判断所需信息，详细数据按需展开。

卡片主信息：

- 资产名。
- 类型标签。
- 状态标签：启用、草稿、退场。
- 可见性标签：公开、隐藏、剧透。
- 首次章节 / 末次章节。
- 一句摘要，最多展示两行。

卡片调度区：

- 用途分段按钮：`可用`、`必用`、`禁揭`、`推进`、`埋线`、`回收`、`暂停`。
- 揭示等级分段按钮：`不揭示`、`线索`、`部分`、`完整`。
- 状态变化输入默认折叠，点击后展开填写。

卡片辅助信息：

- 约束和当前状态从原始长文本改为短标签。
- 每组最多展示 3 到 5 个标签，剩余内容通过 `详情` 展开。
- `编辑`、`删除` 保持为次级操作，避免抢占调度确认区的视觉优先级。

### 3. 资产池浏览

类型 Tabs 保留，但展示逻辑调整为服务筛选结果：

- 默认展示本章相关资产，也就是已配置调用的资产。
- 用户点 `未配置` 时展示当前类型下未配置的资产，方便补充调用。
- 用户切换类型时，筛选条件仍然生效。
- 空状态文案说明当前筛选没有命中，而不是简单显示“暂无设定”。

### 4. 新资产候选和状态变更

第一版只做轻量视觉整理，不改变流程：

- 新资产候选保留当前入库、改名、合并、过场的处置能力。
- 状态变更保留当前选择和应用能力。
- 后续版本再改成完整审核队列和 diff 样式。

## 数据流

复用当前 `SettingWorkshopPanel` 的数据加载：

- `/novel/projects/:projectId/settings`
- `/novel/chapters/:chapterId/settings-usage`
- `/novel/projects/:projectId/reviews`

新增的前端派生数据：

- `usageSummary`：从 `usage` 计算各用途数量。
- `activeUsageFilter`：当前筛选项。
- `filteredSettings`：结合 `activeType`、`usageMap`、`activeUsageFilter` 后得到的展示资产。
- `compactSettingTags`：从 `constraints_json` 和 `state_json` 提取短标签。

保存仍使用现有接口：

- `PUT /novel/chapters/:chapterId/settings-usage`

## 交互规则

- 修改用途后立即更新本地 `usage` state，但不自动提交。
- `禁揭` 自动设置 `forbidden=true`、`required=false`、`allowed=false`。
- `必用`、`推进`、`埋线`、`回收` 自动设置为 required。
- `埋线` 默认最低揭示等级为 `线索`。
- `回收` 默认最低揭示等级为 `部分`。
- `暂停` 不等于禁揭，它表示本章不主动推进，但仍允许上下文提及。
- `未配置` 筛选展示没有显式章节调用记录的资产。

## 错误处理

- 数据加载失败继续使用现有 `message.error('设定工坊加载失败')`。
- 保存失败继续使用现有失败提示，不清空用户本地修改。
- activeChapter 缺失时，调度区显示不可保存状态，避免用户误以为调用已绑定到章节。

## 测试与验证

实现阶段需要覆盖：

- `usageSummary` 对 required、forbidden、advance、plant、payoff、pause 的计数。
- 筛选逻辑对 `全部`、具体用途、`未配置` 的命中结果。
- 用途切换后 `usage` state 的字段兼容现有保存接口。
- 无章节、无资产、无筛选结果时的空状态。
- 浏览器验证桌面宽度下任务中心不被挤压，资产卡片长名称不撑破布局。

## 验收标准

- 打开设定资产页后，用户能先看到本章调用概况，而不是先进入资产类型列表。
- 用户可以在一屏内完成常见确认：查看必用、查看禁揭、调整揭示等级、保存本章调用。
- 长约束和长状态不再以大段原始文本占据主列表。
- 原有新增设定、编辑设定、删除设定、自动匹配和保存调用能力仍可用。
