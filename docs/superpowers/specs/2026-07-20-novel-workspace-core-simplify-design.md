# 小说工作台核心功能收敛设计

**日期:** 2026-07-20  
**状态:** 待确认  
**范围:** 小说大厅 + 项目工作台信息架构与页面级重构（前端为主，后端能力不砍）  
**目标:** 页面只突出 6 块核心能力，去掉重复入口与运营噪音，让主路径一眼可读、一步可做

---

## 1. 问题定义

当前工作台能力完整，但主界面被“长线运营 / 自动化 / 诊断工具”淹没。

典型症状：
- 顶栏 6 个一级 Tab，彼此职责交叉
- 同一动作多入口（复检、补材料、写正文、规划）
- 写完后不知道该复检、同步状态，还是写下一章
- 版本管理有能力，却没有清晰产品位
- 大厅像第二工作台（治理卡、知识投喂、源缓存并列）

**本次不是功能删除后端能力，而是 UI 收敛与路径重组。**  
高级能力保留在代码与次级入口，不进主视线。

---

## 2. 核心能力定义（唯一主叙事）

| # | 核心能力 | 用户一句话 | 成功标准 |
|---|---|---|---|
| 1 | 项目创建 | 我想开一本书 | 3–5 步创建，评分满意后开书 |
| 2 | 骨架大纲创建 | 这本书骨架是什么 | 能看/生成/补齐卷纲与章纲，并进入写作 |
| 3 | 正文创作 | 写这一章 | 选章→补材料→生成/手改→保存 |
| 4 | 复检修订 | 这一章能不能过 | 复检→问题→修订→状态同步 |
| 5 | 资产关联 | 角色设定有没有跟上 | 角色/设定可见、本章关联清楚 |
| 6 | 版本管理 | 刚才那版还能回去吗 | 历史、对比、回滚一处完成 |

非核心（默认隐藏/次级）：
- 自动创作导演、无人值守
- 生产运营整页、商业工具箱全集
- 长线作战台/发布节奏/百万里程碑/读者试读雷达
- 质量基准、一致性图、创意卡片、Agent 审计等调试工具
- 大厅知识投喂/源缓存（保留入口，不占主屏）

---

## 3. 设计原则

1. **一条主路径，不强制旁路**  
   `创建 → 大纲 → 写作 → 复检/修订 →（同步状态）→ 下一章`  
   资产与版本服务主路径，不另起平行主线。

2. **一级入口 ≤ 3**  
   工作台主 Tab 收敛为：`大纲 | 写作 | 资产`。  
   复检修订并入写作闭环；版本并入写作右栏/本章面板。

3. **一状态一主按钮**  
   任一时刻只强调 1 个主操作 + 最多 2 个次操作。  
   禁止同功能按钮在中心条、驾驶舱、右栏、弹窗同时常驻。

4. **状态先于功能**  
   用章节状态机驱动 UI，而不是把所有工具平铺。

5. **高级能力不删，降权**  
   统一进入「更多工具」；需要时 1 次点击可达，默认不出现。

6. **先改壳，后改骨**  
   第一阶段只改信息架构与可见性，尽量不改后端 API；  
   第二阶段再精简组件内部密度。

## 4. 目标信息架构

### 4.1 全局

```text
/novel                         大厅（项目列表 + 新建）
/novel/workspace/:id           项目工作台
  ├ tab=outline                大纲
  ├ tab=writing                写作（含复检修订 + 版本）
  └ tab=assets                 资产
更多工具（抽屉/下拉，非主 Tab）
  ├ 自动创作 / 无人值守
  ├ 生产诊断 / 商业工具
  ├ 任务中心
  ├ 写作圣经（也可从资产进入）
  ├ 导出交付
  └ 调试类工具
```

### 4.2 主 Tab 映射（从旧到新）

| 旧 Tab | 新归属 |
|---|---|
| 自动创作 `autoCreation` | 更多工具 → 自动创作 |
| 故事规划 `storyPlanning` | 主 Tab「大纲」并大幅瘦身 |
| 章节写作 `chapterWriting` | 主 Tab「写作」 |
| 设定资产 `storyAssets` | 主 Tab「资产」 |
| 质检修订 `qualityRevision` | 并入「写作」本章状态区（不再独立主 Tab） |
| 生产运营 `productionOps` | 更多工具 → 生产工具 |

兼容策略：
- 保留旧 `WorkspaceArea` 枚举值一段时间，路由/深链映射到新区
- 旧 action 的 `workspace_area: qualityRevision | productionOps | autoCreation` 映射到新位置，不炸现有 recommendation/serial pipeline

### 4.3 工作台壳层布局

```text
┌──────────────────────────────────────────────────────────┐
│ 返回 | 书名 | [大纲] [写作] [资产] | 模型 | 任务角标 | 更多 │
├──────────┬───────────────────────────────┬───────────────┤
│ 章节目录  │  当前主区内容                   │ 情境侧栏      │
│ （始终）  │  outline / writing / assets    │ 随 Tab 变化   │
└──────────┴───────────────────────────────┴───────────────┘
```

- 左栏：始终是章节目录（大纲模式下可显示规划进度标记）
- 中区：当前主 Tab
- 右栏：随 Tab 切换内容，不再堆“全能参考面板”

右栏按 Tab：
- 大纲：卷/章结构摘要、缺口列表
- 写作：本章要点 / 质检结果 / 版本
- 资产：本章关联资产 / 快捷建卡

## 5. 六大核心区详细设计

### 5.1 项目创建

**页面：** 大厅 + `NovelCreateWizard`

**主路径**
1. 大厅点「新建小说」
2. 输入种子 / 选题材题材引导
3. 生成基础草稿
4. 看评分与关键字段，满意则创建
5. 自动进入工作台「大纲」Tab（若大纲已够写第 1 章，可提示去写作）

**大厅只保留**
- 项目卡片：书名、进度、下一动作
- 新建按钮
- 进入工作台

**大厅降权**
- 知识投喂、源缓存 → 顶栏「资料」或项目内更多工具
- 治理卡片三列 → 收敛为项目卡片上的一枚状态标签 + 下一动作按钮

**不做**
- 不在创建流中塞长线运营概念
- 不把创建向导做成完整工作台

### 5.2 骨架大纲创建（大纲 Tab）

**目标用户任务**
- 看清整书骨架
- 生成/补齐缺失大纲
- 确认当前可写章节后进入写作

**页面结构（瘦身后）**

```text
[概览条]
  当前卷 · 已规划章数 · 已写章数 · 主按钮

[结构树 / 列表]
  卷
   └ 章（目标 / 冲突 / 钩子 / 是否已写）

[缺口条]
  仅展示可行动缺口：缺卷纲 / 缺细纲 / 进度漂移
  每项一个按钮
```

**常驻操作**
- 生成/补齐当前卷大纲
- 更新滚动规划（未来 N 章）
- 进入本章写作

**移出大纲主屏（进更多工具或折叠「长线视图」）**
- AI 长篇创作流水线整卡
- 长篇作战台
- 核心契约雷达
- 连载发布节奏台
- 百万字里程碑地图
- 长篇记忆胶囊
- 连载治理中枢
- 读者试读/信任账本/创新雷达

**空态**
- 无大纲：大按钮「生成骨架大纲」
- 有大纲无正文：提示「从第 N 章开始写」

### 5.3 正文创作（写作 Tab · 主区）

**目标布局**

```text
┌─────────────────────────────────────────────┐
│ 本章标题 · 状态芯片 · 字数 · 保存状态          │
│ 主操作条： [主按钮] [次按钮1] [次按钮2]        │
│ 状态说明：一行人话解释为什么是这个按钮          │
├─────────────────────────────────────────────┤
│ 正文编辑器（主视觉）                            │
├─────────────────────────────────────────────┤
│ 可折叠：本章任务要点（目标/冲突/钩子/交接）      │
└─────────────────────────────────────────────┘
右栏：
  [要点] [质检] [版本]  三子 Tab，默认按状态切换
```

**章节状态机（驱动 UI）**

| 状态 | 含义 | 主按钮 | 次按钮 |
|---|---|---|---|
| `empty` | 无正文 | 生成正文 | 补齐材料 / 看任务 |
| `blocked_materials` | 缺材料不能稳写 | 补齐材料 | 强制继续（高级） |
| `writing` | 有草稿，未完成闭环 | 继续编辑/重写 | 复检 |
| `written_unchecked` | 已有正文，未复检 | 复检 | 重写 |
| `needs_revision` | 复检有问题 | 一键修订 | 查看问题 / 复检 |
| `needs_state_sync` | 质检过，故事状态未同步 | 同步故事状态 | 复检 |
| `ready_next` | 本章可过 | 写下一章 | 版本 / 回看 |
| `failed_admission` | 生成被准入拦截 | 按失败原因修复 | 查看原因 |

规则：
- 主按钮唯一，来自状态机，不再同时显示“生成+复检+流水线+无人值守”
- 生成模式默认 `draft_only` 或项目级默认；高级模式放更多里
- 风格样本、诊断、流水线、场景卡默认折叠「高级写作」

**中心条重构（替换现状多 strip 堆叠）**
- 删除/合并：delivery chips、queue strip、handoff strip、draft brief strip 的重复展示
- 改为单一 `ChapterActionBar` + 可选折叠 `ChapterBriefPanel`

**写作页禁止再出现**
- 「无人值守」主按钮
- 「生产运营」跳转主按钮
- 多个复检入口并排

### 5.4 复检修订（写作闭环，非独立主 Tab）

**放置**
- 写作 Tab 状态条 + 右栏「质检」
- 旧 `qualityRevision` 整页能力迁入，不再占顶栏

**闭环步骤 UI（横向一步条，仅 4 步）**

```text
正文 → 复检 → 修订 → 状态同步 → 下一章
```

每步显示：
- 当前是否完成
- 未完成时为什么（一行）
- 对应唯一操作

**报告展示**
- 默认：问题列表（严重度 + 一句话 + 定位）
- 展开：详细证据
- 主操作：按报告修订
- 次操作：仅复检 / 人工忽略（若已有策略）

**故事状态同步**
- 未同步时，状态条明确：`质检已过，故事状态未同步，写下一章可能漂移`
- 主按钮变成「同步故事状态」
- 同步成功后才进入 `ready_next`

**旧质检页处理**
- 组件逻辑复用到写作右栏/状态区
- 路由 `qualityRevision` → `writing` 并自动打开质检子面板

### 5.5 资产关联（资产 Tab）

**主屏只留 3 块**

1. **角色**  
   列表 + 当前状态摘要 + 新建/补全
2. **设定**  
   世界观/规则/地点等关键设定
3. **本章关联**  
   当前章实际用到 / 应引用的资产；缺失提示 + 一键补建

**次级（页内二级，不进顶栏）**
- 写作圣经
- 参考作品配置
- 设定图谱（可视化）

**移出主视线**
- 一致性图、创意卡片、复杂图谱编辑默认进更多工具

**与写作联动**
- 写作缺材料时，「补齐材料」可跳资产并高亮缺口
- 写完后新角色提示「已发现未建卡角色」→ 资产「本章关联」

### 5.6 版本管理（写作右栏 · 版本）

**产品位**
- 不设主 Tab
- 固定在写作右栏第三子页「版本」
- 编辑器顶栏保留「版本」快捷，打开同一面板

**能力**
- 当前版本标记
- 历史列表（时间、来源：手改/生成/修订/回滚）
- 对比（当前 vs 选中）
- 回滚（确认后）
- 生成失败未入库的说明：不产生脏版本

**文案区分**
- 版本 ≠ 运行记录 ≠ 任务中心  
- 版本只回答：正文内容历史

## 7. 状态与推荐动作统一

### 7.1 单一事实来源

建立前端 `ChapterWorkflowPresenter`（命名可调整），输入：
- 章节正文是否存在
- 最新质检报告
- 修订报告
- 故事状态同步结果
- preflight/admission 失败
- 材料 readiness

输出：
- `phase`（上表状态）
- `primaryAction`
- `secondaryActions[]`（≤2）
- `reasonText`
- `panelToOpen`（brief/quality/version/assets）

现有 `writingCockpitModel` / `writingRecommendation` / `serialPipelineModel` 逐步收敛为给 Presenter 提供数据，不再各自直接往 UI 塞多套按钮。

### 7.2 去重规则

| 动作 | 唯一主入口 |
|---|---|
| 生成正文 | 写作状态条主按钮 |
| 复检 | 写作状态条（状态=已写待检时） |
| 修订 | 写作状态条（状态=待修订时） |
| 同步故事状态 | 写作状态条（状态=待同步时） |
| 补齐材料 | 写作状态条或 preflight 弹窗（同源 action） |
| 回滚版本 | 版本面板 |
| 编辑资产 | 资产 Tab |

驾驶舱若保留，改为**只读状态摘要 + 同一个 primaryAction**，不再复制一套按钮矩阵。

## 8. 分阶段实施

### Phase 0 — 契约与兼容（0.5–1 天）
- 定义新 `WorkspacePrimaryTab = outline | writing | assets`
- 旧 area 映射表
- 深链/action router 兼容
- 开关：`workspaceCoreSimplify`（可选，便于回滚）

### Phase 1 — 壳层收敛（优先，可独立上线）
- 顶栏 6 Tab → 3 Tab
- 生产运营/自动创作/独立质检页降级到更多
- 大厅减噪
- 不破坏现有生成/复检 API

**验收：** 用户只看到 3 主 Tab，旧功能仍可从更多进入

### Phase 2 — 写作页重构（核心体验）
- `ChapterActionBar` + 状态机
- 合并多 strip
- 右栏三子 Tab：要点/质检/版本
- 复检修订闭环可视化
- 驾驶舱降为摘要或移除重复主按钮

**验收：** 写一章时始终只明白“现在该按哪个按钮”

### Phase 3 — 大纲页瘦身
- 只留结构树 + 缺口行动 + 滚动规划
- 长线作战卡折叠/迁移

**验收：** 大纲页 10 秒内找到“补齐大纲/去写作”

### Phase 4 — 资产页收敛
- 三角色：角色/设定/本章关联
- 图谱与圣经二级化

**验收：** 从写作缺材料可跳到对应资产缺口

### Phase 5 — 清理与测试
- 删除不可达 UI 或标记 deprecated
- 更新 shell 契约测试
- 手工走通：创建→大纲→写第1章→复检→修订→同步→第2章
- 回归：旧 recommendation action 仍可路由

## 10. 明确不做（本轮）

## 11. 风险与缓解

| 风险 | 缓解 |
|---|---|
| 用户找不到旧入口 | 更多菜单 + 首周“功能去哪了”轻提示 |
| recommendation/serial 路由失效 | 兼容映射表 + 单测覆盖旧 area |
| 写作页一次改太大 | Phase1 先藏 Tab，Phase2 再重构写作 |
| 状态机判断与真实业务不一致 | Presenter 单测用真实章节夹具 |
| 回归面大 | 每 Phase 可独立合并，功能开关可回滚 |

---

## 12. 验收标准（产品）

1. 进入任意已有项目，顶栏只有 3 个主工作区（+ 更多）。
2. 新用户不查文档也能完成：创建→出大纲→写第1章→复检→（如需）修订/同步→第2章。
3. 任一章节状态只突出 1 个主按钮；同功能不在 3 处以上同时常驻。
4. 复检/修订/状态同步原因可读，不再“卡住却不知道为什么”。
5. 版本可在写作页 2 次点击内完成对比或回滚。
6. 自动创作/生产运营仍可用，但不挡主路径。
7. 现有项目数据零迁移；刷新不丢正文与版本。

---

## 13. 推荐落地顺序（确认后执行）

1. **先 Phase 1 壳层收敛**（收益最大、风险可控）
2. **再 Phase 2 写作状态条与右栏**（直接解决“迷茫”）
3. 大纲瘦身 → 资产收敛 → 清理测试

## 14. 待你拍板的决策点

1. **主 Tab 是否确定为 3 个：大纲 / 写作 / 资产？**  
   （复检不独立成 Tab）
2. **驾驶舱左侧大面板：降级为摘要条，还是写作页彻底去掉？**  
   推荐：降级为可折叠摘要，主按钮与状态条共用。
3. **自动创作：完全进更多，还是大纲/写作里留一个“批量”次入口？**  
   推荐：完全进更多。
4. **是否需要功能开关做灰度？**  
   推荐：要，默认开新壳，可回旧 Tab 一周。

确认以上决策后，可进入 `writing-plans` 拆分 Phase 1 实施任务并开工。
