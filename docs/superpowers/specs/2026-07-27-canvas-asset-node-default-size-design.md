# 画布资产节点默认尺寸设计

日期：2026-07-27
状态：已确认
范围：资产库“发送到画布”创建的 `loadAsset` 节点

## 背景

资产库侧边栏把图片或视频资产发送到画布时，创建的 `loadAsset` 节点没有显式宽高。React Flow 因而会在首次渲染时测量节点内容，媒体的固有尺寸可能把节点撑得远大于画布中的其他节点。

项目现有生成节点、自动布局、折叠恢复等路径已经使用 `360 × 380` 作为标准节点尺寸。

## 目标

- 之后从资产库发送到画布的新资产节点默认固定为 `360 × 380`。
- 图片和视频只在该节点的预览区域内等比缩放，不决定节点外框尺寸。
- 用户创建节点后仍可使用现有 `NodeResizer` 自由调整宽高。

## 非目标

- 不迁移或修改旧画布中已经存在的资产节点。
- 不改变通过节点搜索菜单手动创建的空 `loadAsset` 节点。
- 不改变节点最小尺寸、折叠行为或媒体预览内容。
- 不为不同资产类型引入不同默认尺寸。

## 方案

在 `CanvasPage` 的资产库 `onAddToCanvas` 回调里，为新建的 `loadAsset` 节点写入：

```ts
style: { width: 360, height: 380 }
```

尺寸在节点进入画布状态前就已明确，因此 React Flow 不需要用图片或视频的固有尺寸决定节点外框。现有 `LoadAssetNode` 已通过 `maxWidth: '100%'`、`maxHeight: '100%'` 和隐藏溢出把媒体限制在预览区域内，无需修改其预览逻辑。

选择在创建入口设置尺寸，而不是为所有 `loadAsset` 节点增加全局默认值，可以精确满足“只影响之后发送到画布的节点”的范围要求。

## 数据流

1. 用户在资产库点击“发送到画布”。
2. `CanvasPage` 计算新节点位置。
3. `addNode` 收到带 `style.width = 360`、`style.height = 380` 的 `loadAsset` 节点。
4. React Flow 按显式尺寸渲染节点。
5. 媒体在预览区域内等比缩放；用户之后可手动缩放节点。

## 测试与验收

先增加回归测试，证明当前发送入口没有为资产节点写入显式尺寸；测试应在实现前失败。随后做最小实现并验证：

- 资产库发送入口创建的 `loadAsset` 节点包含 `style: { width: 360, height: 380 }`。
- 现有 `LoadAssetNode` 行为测试继续通过。
- 画布相关定向测试通过。
- Web 前端生产构建通过。

人工验收：发送一张高分辨率横图或竖图到画布，节点初始外框应为 `360 × 380`，图片完整约束在预览区内；拖拽缩放器后节点仍能正常改变尺寸。

## 风险与回退

本次只向新节点对象增加 React Flow 已支持的 `style` 字段，不涉及持久化结构迁移。若需回退，只需移除该创建入口的显式尺寸；旧画布数据与其他创建路径不受影响。
